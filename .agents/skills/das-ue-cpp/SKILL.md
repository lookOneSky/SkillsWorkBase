# Unreal C++ 规范

## Plan 模式

- Plan 模式下不得写入文件。直接在聊天中交付覆盖整个任务的完整 Markdown 原文。涉及本技能的计划交付以本节为准。
- 每个涉及的 `.h` 或 `.cpp` 文件各占一块。标明文件路径，逐项列出拟新增、替换或删除的内容、对应行号（新增内容标明插入位置，新文件使用拟定行号），以及所属类或函数（如有）。用 `cpp` 围栏代码块展示修改后的代码片段和必要上下文。
- 用 HTML `<div style="border: 1px solid #4B5563">` 包裹每个文件块，容器标签与块内的 Markdown 内容之间留空行。
- 在所有文件块之后列出验证步骤。拟改内容有变化时，在聊天中重发完整计划并重新请用户确认。用户确认后进入执行阶段修改代码。

## 代码规范

- 头文件的函数声明及参数写在同一行。其余代码按语句和逻辑换行，左右花括号各占一行。
- 类和结构体的成员变量放在所有成员函数之后。结构体定义放在类外。
- 类名与对应头文件、源文件的文件名（不含扩展名）一致。
- 临时变量用小写类型前缀加大驼峰名称。类和结构体的非 `UPROPERTY()` 成员变量在此基础上加 `m` 前缀，`UPROPERTY()` 成员变量只用大驼峰名称。
- 修改已有逻辑时，尽量减少改动行数，避免无关的重排、格式化和重构。
- 尽量使用具名函数，少用 lambda。
- 辅助逻辑优先写成成员函数，尽量少用文件作用域或命名空间作用域的自由函数。
- 仅进行代码修改与静态检查，不执行编译或构建。

## 代码说明

- 说明代码行为或问题原因时，只用必要的文字讲清要点。引用已核实的代码片段，附可点击的文件路径、准确行号和所属类或函数。代码无法直接证明的结论标注为推断或待验证。
