# Unreal C++ 代码与改动报告规范

UE 相关任务一律适用，无论是否涉及 C++ 或是否明确要求 Plan。

- 无论处于 Plan 模式、普通执行模式，还是修改后的结果回复，只要回复涉及代码改动（包括拟议改动与已完成改动），都必须自行选择位置创建或更新专用 `.md` 代码改动报告，并在回复中提供文件链接。
- 报告以代码为主，只保留理解当前变更所需的最少文字，并明确区分拟议改动与已完成改动。
- 只展示当前需要新增或修改的代码及定位所需的必要上下文，省略无关代码，不展示完整文件。
- 说明 C++ 代码改动时，必须附带修改处前后必要的原有代码上下文，并标明文件路径、所属函数或类及插入、替换或删除的位置，方便确认修改位置。
- 所有 C++ 代码使用带 `cpp` 语言标识的 Markdown 围栏代码块。
- 头文件中的函数声明（含参数）写成一行；其余代码按语句和逻辑换行，左右花括号分别独占一行。
- 修改已有逻辑时，尽量减少对原有代码的改动行数，避免无关的重排、格式化或重构。
- 类名必须与对应头文件、源文件的文件名（不含扩展名）保持一致。
- 临时变量名使用“类型前缀 + 驼峰名称”：小写首字母表示类型，后续名称使用大驼峰。
- 非 `UPROPERTY()` 成员变量在临时变量命名规则前增加 `m` 前缀。
- `UPROPERTY()` 成员变量使用大驼峰名称，首字母大写，不增加 `m` 或类型前缀。
- 不要在类内部定义结构体，将结构体定义放在类外部。
- 结构体成员变量使用与类成员变量相同的命名规则。
- C++ 实现尽量不使用 lambda，优先提取为具名函数。
- 不执行任何编译命令或构建操作，仅进行代码修改与静态检查。
