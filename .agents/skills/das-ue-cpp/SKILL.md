# Unreal C++ 规范

## 代码规范

- 在 Markdown 中用 `cpp` 围栏代码块展示 C++ 代码。Plan 模式下，将本次所有拟改内容集中写入同一个 `.md` 计划文件。文件中列出拟新增、替换或删除的代码，逐项标明文件路径、修改位置及所属类或函数（如有）。用 `cpp` 围栏展示修改前后的代码片段及必要上下文，省略无关代码。

  将计划文件链接发给用户，等用户确认后再进入执行阶段修改代码。拟改内容有变化时，更新同一份文件并重新请用户确认。

- 说明代码行为或问题原因时，引用已核实的代码片段，附可点击的文件路径、准确行号和所属类或函数。代码无法直接证明的结论标注为推断或待验证。
- 头文件的函数声明及参数写在同一行。其余代码按语句和逻辑换行，左右花括号各占一行。
- 类和结构体的成员变量放在所有成员函数之后。结构体定义放在类外。
- 类名与对应头文件、源文件的文件名（不含扩展名）一致。
- 临时变量用小写类型前缀加大驼峰名称。类和结构体的非 `UPROPERTY()` 成员变量在此基础上加 `m` 前缀，`UPROPERTY()` 成员变量只用大驼峰名称。
- 修改已有逻辑时，尽量减少改动行数，避免无关的重排、格式化和重构。
- 尽量使用具名函数，少用 lambda。
- 辅助逻辑优先写成成员函数，尽量少用文件作用域或命名空间作用域的自由函数。
- 仅进行代码修改与静态检查，不执行编译或构建。
